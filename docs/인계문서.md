# NOWFLIX 키오스크 인계 문서

병원 담당자와 이후 유지보수 담당자를 위한 **전체 인수인계 문서**입니다.
설치 방법은 `설치가이드.md`, 일상 운영은 `운영가이드.md` 를 보세요. 이 문서는
**"무엇으로 이루어져 있고, 무엇을 보관해야 하며, 문제가 생기면 어떻게 하는가"** 를 다룹니다.

## 1. 이 시스템은 무엇으로 이루어져 있나 (한 장 요약)

| 구성 요소 | 역할 | 어디에 있나 |
|---|---|---|
| **태블릿 앱 (NOWFLIX)** | 병원에 놓인 태블릿에서 실행되는 키오스크 앱. 유튜브 재생목록을 넷플릭스처럼 보여주고, 화면을 앱 하나에 잠근다. | 태블릿 5대 (`kr.prism.nowflix`) |
| **관리자 웹** | 파트·재생목록·설정을 바꾸는 웹사이트. 병원이 직접 사용. | https://nowflix-admin.vercel.app (Vercel) |
| **데이터베이스 / 저장소 (Supabase)** | 파트 목록, 설정(복귀시간·PIN·헤더), 포스터 이미지를 저장. 앱과 웹이 여기서 읽고 쓴다. | Supabase 프로젝트 `nowflix-kiosk` (서울 리전) |
| **유튜브 데이터 (Google)** | 재생목록의 영상 목록·제목·길이·조회수를 가져옴. | Google Cloud (YouTube Data API v3 키) |

동작 흐름: **관리자 웹**에서 병원이 내용을 바꾸면 → **Supabase**에 저장되고 →
**태블릿 앱**이 (30분마다 또는 "설정 새로고침" 시) 그 내용을 받아와 화면에 반영합니다.
영상 자체는 **유튜브**에서 실시간으로 재생됩니다.

## 2. 계정 목록 — 무엇에 쓰고 어디서 관리하나

이 3개 계정은 시스템의 핵심입니다. **로그인 정보를 병원이 안전하게 인계받아 보관**하세요.

### ① 구글 (Google) — 유튜브 데이터
- **쓰임**: 유튜브 재생목록/영상 정보를 가져오는 **YouTube Data API v3 키**. 태블릿에 심어져 있습니다.
- **관리 위치**: Google Cloud Console (`https://console.cloud.google.com`) → "API 및 서비스" → 사용자 인증 정보.
- **주의**: 이 키에는 하루 사용량 한도(quota)가 있습니다. 태블릿 대수·재생목록 수가 크게 늘면 한도를 올려야 할 수 있습니다.
- 재생목록 자체를 소유·관리하는 유튜브 채널 계정도 함께 인계받아 두세요.

### ② Supabase — 데이터베이스 + 이미지 저장소
- **쓰임**: 파트 목록, 설정값(복귀시간/PIN/헤더/웹 비밀번호), 포스터 이미지를 저장. 앱·웹의 공용 저장소.
- **관리 위치**: `https://supabase.com` 로그인 → 프로젝트 **`nowflix-kiosk`** (리전: ap-northeast-2 서울).
- **키 두 종류**:
  - `anon` 키 — 앱이 **읽기 전용**으로 사용(태블릿에 들어 있음).
  - `service_role` 키 — 관리자 웹 서버만 사용하는 **쓰기 권한** 키. **절대 외부에 노출 금지**(웹 서버 환경변수에만 있음).

### ③ Vercel — 관리자 웹 호스팅
- **쓰임**: 관리자 웹(`nowflix-admin.vercel.app`) 을 호스팅. 웹이 Supabase에 안전하게 쓰도록 키를 환경변수로 보관.
- **관리 위치**: `https://vercel.com` 로그인 → 프로젝트 **`nowflix-admin`** (함수 리전: icn1 서울).
- 환경변수 5종(Supabase URL/anon/service_role, 유튜브 키, 세션 비밀)이 여기에 암호화 저장돼 있습니다. 저장소(git)에는 없습니다.

> 🔎 개발용 임시 프로젝트도 하나 있습니다 → **9번 항목** 참고 (납품 후 삭제 대상).

### 이관 절차 (병원 명의로 옮기기)

**0단계 — 먼저 준비할 것**
- 병원 명의 이메일 계정 1개(예: `it@병원도메인`). 개인 지메일 대신 **병원이 계속 통제할 수 있는 주소**여야 합니다.
- 그 이메일로 Supabase·Vercel·Google 계정을 각각 가입해 둡니다.

**① Supabase — 조직 소유권 이전**
1. 개발자 계정으로 `https://supabase.com/dashboard` 접속 → 조직 `nowflix` → **Settings → Team** (`.../org/_/team`).
2. **Invite member** 로 병원 이메일을 초대하고 역할을 **Owner** 로 지정합니다.
3. 병원 담당자가 메일의 초대를 수락합니다. (이 시점에 Owner 2명)
4. 병원 담당자 로그인 상태에서 개발자 계정을 **Remove member** 합니다. → 조직·프로젝트·DB가 병원 소유가 됩니다.
5. **프로젝트 자체는 옮기지 않습니다.** 조직만 넘기면 프로젝트 `nowflix-kiosk` 도 함께 넘어가고,
   URL·ref·anon 키가 그대로라 **앱/웹 재배포가 필요 없습니다.** (프로젝트를 다른 조직으로 옮기면 ref가 바뀌어 태블릿 5대를 전부 재설치해야 합니다 — 하지 마세요.)
6. 이관 후 병원 계정에서 **MFA(2단계 인증)** 를 켜세요. 현재 미설정 상태입니다.
7. Settings → Billing 의 결제 수단도 병원 것으로 교체합니다(현재 free 플랜이라 등록 없음).

**② Vercel — 프로젝트 이전**
1. 병원 계정으로 Vercel 가입 후, 개발자 계정에서 팀 **Settings → Members** 로 병원 이메일을 **Owner** 초대 → 수락 → 개발자 제거.
   (팀 통째로 넘기면 `nowflix-admin` 의 도메인 `nowflix-admin.vercel.app` 과 환경변수 5종이 그대로 유지됩니다.)
2. 팀을 넘기지 않고 **프로젝트만** 옮기려면: `nowflix-admin` → **Settings → General → Transfer Project** → 병원 팀 선택.
   - ⚠️ 이 방식은 **환경변수 5종**(`SUPABASE_URL`/`SUPABASE_ANON_KEY`/`SUPABASE_SERVICE_ROLE_KEY`/`YOUTUBE_API_KEY`/`SESSION_SECRET`)을
     **옮긴 뒤 직접 다시 입력**해야 하고, `production` 값은 sensitive 타입이라 화면에서 다시 볼 수 없습니다.
     Supabase 대시보드에서 키를 새로 복사해 채워야 합니다.
   - ⚠️ 도메인 `nowflix-admin.vercel.app` 도 다시 붙여야 하며, 그동안 관리자 웹이 잠시 끊깁니다.
   - → **가능하면 1번(팀 멤버 교체) 방식을 쓰세요.**
3. GitHub 연동을 쓰는 경우, 병원 계정에도 저장소 접근 권한을 부여해야 자동 배포가 계속됩니다.

**③ Google (YouTube Data API)**
1. `https://console.cloud.google.com` → 해당 프로젝트 → **IAM 및 관리자 → IAM** 에서 병원 이메일을 **소유자(Owner)** 로 추가.
2. **IAM 및 관리자 → 설정 → 프로젝트 이전** 또는 결제 계정을 병원 결제 계정으로 변경.
3. 병원 소유자 확인 후 개발자 계정을 IAM에서 제거.
4. ⚠️ **API 키 값 자체는 바뀌지 않으므로 태블릿 재설치는 불필요**합니다. 단 키를 새로 발급하면
   `local.properties` 수정 + APK 재빌드 + 태블릿 5대 재설치가 필요하니, 이관만 하고 키는 유지하세요.
5. 재생목록을 소유한 **유튜브 채널 계정**도 함께 인계하세요. 채널이 없어지면 앱 목록이 비게 됩니다.

**④ 이관 완료 후 체크리스트**
- [ ] Supabase 조직 멤버 목록에 병원 계정만 남았는가 (Owner)
- [ ] Vercel 팀 멤버 목록에 병원 계정만 남았는가
- [ ] `https://nowflix-admin.vercel.app` 로그인 정상 (200)
- [ ] 태블릿에서 파트 목록·영상 목록이 정상 표시 (앱 재시작 후)
- [ ] `nowflix-release.jks` 와 비밀번호를 병원이 별도 보관 중인가 → **6번 항목**
- [ ] 각 계정에 MFA 활성화

## 4. 문제가 생겼을 때 — 순서대로 시도

**위에서 아래로** 순서대로 시도하세요. 대부분 1~2번에서 해결됩니다. 5번(재설치)은 최후 수단입니다.

1. **앱 재시작** — 화면이 멈췄거나 영상이 안 나올 때.
   관리자 진입(오른쪽 위 모서리 3초 → PIN) → **"앱 종료"** → 앱이 자동으로 다시 뜹니다.
2. **태블릿 재부팅** — 앱 재시작으로 안 되면 태블릿 전원을 껐다 켭니다.
   부팅되면 NOWFLIX가 자동 실행됩니다.
3. **PIN으로 관리자 진입** — 설정을 확인/새로고침하거나 상태를 점검할 때.
   오른쪽 위 모서리 3초 → PIN 입력 → 관리자 화면. "설정 새로고침"으로 최신 설정을 즉시 적용.
4. **완전 해제** — 태블릿을 일반 안드로이드로 되돌려야 할 때(수리·반납 등).
   관리자 화면 → **"키오스크 모드 완전 해제"** → 확인. 공장초기화 없이 잠금이 풀립니다.
   (PIN도 앱도 못 쓸 만큼 앱이 망가졌다면 PC에서 `scripts/uninstall.sh` 또는 `docs/kiosk-recovery.md`.)
5. **재설치** — 앱이 크게 손상됐을 때. PC 연결 후 `scripts/install.sh` 재실행.
   자세한 절차는 `docs/설치가이드.md`.

> 참고 문서: 잠금 해제/복구 명령 모음 → `docs/kiosk-recovery.md`,
> 설치 현장 점검표 → `docs/onsite-checklist.md`.
>
> **태블릿이 아니라 "관리자 웹 로그인"이 안 되는 경우는 원인이 다릅니다 → 5번 항목**을 보세요.

## 5. 관리자 웹 로그인이 갑자기 안 될 때 — Supabase 자동 일시정지

> 2026년 8월 25일 실제로 발생한 장애입니다. **원인은 비밀번호가 아닙니다.**
> 아래 순서만 따라 하면 비개발자도 5~10분 안에 되살릴 수 있습니다.

### 무슨 일이 일어난 건가요
Supabase **무료 요금제**는 프로젝트에 **7일 동안 아무 접속도 없으면 자동으로 잠시 멈춥니다**
(일시정지, pause). 데이터가 지워지는 것은 아니고 **잠자기 상태**가 되는 것입니다.
멈춰 있는 동안 관리자 웹은 데이터베이스를 읽지 못해 로그인 자체가 되지 않습니다.

### 이런 증상이면 이 문제입니다
- 관리자 웹에서 **맞는 비밀번호를 넣어도** 로그인이 안 됩니다.
- 화면에 **"일시적인 서버 문제입니다. 잠시 후 다시 시도해주세요."** 가 뜹니다.
  (비밀번호를 틀렸을 때는 대신 "비밀번호가 올바르지 않아요." 가 뜹니다. **메시지로 구분하세요.**)
- 새로고침하거나 다른 PC·휴대폰에서 해도 똑같습니다.
- **로비 태블릿은 대체로 그대로 잘 나옵니다** — 태블릿은 마지막에 받아둔 설정을 저장해 두기
  때문입니다. 그래서 "웹만 안 되는" 상태로 보입니다.

### 되살리는 방법 (병원 담당자용)
1. `https://supabase.com` 에 접속해 로그인합니다. (계정 정보는 이 문서 **2번 ②** 참고)
2. 프로젝트 목록에서 **`nowflix-kiosk`** 를 클릭합니다.
   멈춰 있으면 이름 옆에 **`PAUSED`(일시정지)** 라고 표시됩니다.
3. 화면 가운데의 **`Restore project`**(또는 `Resume`) 버튼을 누르고, 확인 창에서 한 번 더 누릅니다.
4. **2~5분 기다립니다.** 상태가 `Restoring` → `Active` 로 바뀌면 완료입니다.
   (페이지를 새로고침하며 기다리세요. 데이터는 그대로 복구됩니다.)
5. 관리자 웹(`https://nowflix-admin.vercel.app`)에 다시 로그인해 봅니다. 정상 동작해야 합니다.
6. 그래도 안 되면 유지보수 담당자에게 연락하세요(**7번** 항목의 연락처).

> ⚠️ Supabase 화면에서 `Restore`(되살리기) 와 비슷해 보이는 **`Delete project`(삭제)** 를
> 절대 누르지 마세요. 삭제하면 데이터가 사라집니다.

### 재발 방지 — 3일마다 자동으로 깨우기 (이미 설정됨)
GitHub Actions 에 **`supabase-keepalive`** 워크플로를 넣어 두었습니다.
**3일마다 한 번** Supabase 에 아주 가벼운 조회를 한 번 보내 "사용 중" 상태를 유지합니다.
7일 한도의 절반 이하 주기라, 한 번쯤 걸러도 일시정지되지 않습니다.

- 확인 위치: GitHub 저장소 → **Actions** 탭 → 왼쪽 목록의 **`supabase-keepalive`**.
  초록색 체크(✓)면 정상입니다. **`Run workflow`** 버튼으로 지금 즉시 한 번 돌려볼 수도 있습니다.
- 일시적인 네트워크 오류로는 빨간 불이 켜지지 않습니다. **연속 3회 실패했을 때만 실패(빨강)로
  표시**되며, 저장소 소유자에게 GitHub 알림 메일이 갑니다. 빨간 불이 보이면 위 "되살리는 방법"을 따르세요.
- 이 워크플로는 저장소 시크릿 **`SUPABASE_URL`**, **`SUPABASE_ANON_KEY`** 두 개를 씁니다
  (읽기 전용 anon 키만 사용하며, 쓰기 권한 `service_role` 키는 쓰지 않습니다).
  GitHub 저장소 → Settings → Secrets and variables → Actions 에서 확인할 수 있습니다.
  값은 Supabase 대시보드 → Settings → API 의 `Project URL` 과 `anon public` 입니다.
  시크릿이 없으면 워크플로가 무엇이 빠졌는지 한국어로 알려주며 실패합니다.
- ⚠️ 저장소가 **삭제되거나 60일 이상 아무 커밋도 없으면** GitHub 이 스케줄 실행을 자동으로
  멈춥니다. 그럴 때는 Actions 탭에서 워크플로를 다시 **Enable** 해 주세요.

### 근본적인 해결 — 유료 전환 비용(참고)
자동 깨우기로 충분하지만, **일시정지 자체를 없애려면** Supabase 유료 전환이 가장 확실합니다.

### 안전하게 내려받는 방법 (개발 VM → 내 PC)

> 🚫 **하면 안 되는 것**: git 커밋/푸시, GitHub 릴리즈 첨부, 이메일·카톡·슬랙에 원본 첨부,
> 공개 파일공유 링크. 이 파일은 앱의 도장이라 유출되면 **위조 앱이 기존 앱 위에 덮어씌워질 수 있습니다.**

**방법 A — scp (VM에 SSH로 붙을 수 있으면 가장 안전, 권장)**
```bash
# 내 PC에서 실행
scp <사용자>@<VM주소>:/home/dev/nowflix-kiosk/nowflix-release.jks ~/nowflix-release.jks
sha256sum ~/nowflix-release.jks   # 아래 값과 같아야 함
# 376842971726f8abbca0635944f4efc05551d8fb7b0fc82d825f6f7544adac49
```

**방법 B — 암호를 한 겹 더 씌워서 옮기기 (클라우드/메신저를 거쳐야 할 때)**
```bash
# VM에서: 저장소 밖에 암호화본 생성 (암호는 keystore 비번과 다른 것을 쓸 것)
cd /home/dev/nowflix-kiosk
openssl enc -aes-256-cbc -pbkdf2 -iter 200000 -salt   -in nowflix-release.jks -out /tmp/nowflix-release.jks.enc
# → 이 .enc 파일만 전달하고, 암호는 반드시 다른 경로(전화·대면)로 알려준다

# 받는 쪽에서: 복호화 + 검증
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000   -in nowflix-release.jks.enc -out nowflix-release.jks
sha256sum nowflix-release.jks   # 376842…dac49 와 일치 확인
```

**방법 C — 터미널만 있을 때 (base64 복사·붙여넣기)**
파일이 2,650바이트라 base64로도 3,536자뿐입니다.
```bash
# VM에서 출력 → 전체 선택 복사
base64 -w0 /home/dev/nowflix-kiosk/nowflix-release.jks
# 내 PC에서 붙여넣어 복원
pbpaste | base64 -d > nowflix-release.jks     # macOS
#  또는  파일에 붙여넣은 뒤:  base64 -d jks.b64 > nowflix-release.jks
sha256sum nowflix-release.jks   # 376842…dac49 와 일치 확인
```
⚠️ 방법 C는 **터미널 스크롤 기록·클립보드에 키가 남습니다.** 옮긴 뒤 기록을 지우세요.

**복원 후 정상 확인 (어느 방법이든 공통)**
```bash
keytool -list -keystore nowflix-release.jks -storepass nowflix-kiosk-2026
# → "nowflix, …, PrivateKeyEntry" 1개 + 지문 A4:C7:38:… 가 나오면 정상
```

**보관 위치 권장** — 최소 2곳, 서로 다른 장소에:
1. 병원 담당자의 **비밀번호 관리도구**(1Password/Bitwarden 등)에 파일 첨부 + 비밀번호 함께 저장
2. 유지보수사 보관본 (암호화한 상태로)
3. (선택) 오프라인 USB를 금고 등에 보관
- **파일과 비밀번호를 같은 메일·같은 메시지에 함께 보내지 마세요.**
